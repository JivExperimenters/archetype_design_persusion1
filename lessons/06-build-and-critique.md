# 6. Build and critique your four heroes

[← Gallery](05-example-gallery.md) · [Home](../README.md) · [Submission checklist](../assignment.md#submit)

**You will learn:** a repeatable way to generate, inspect, and explain a set.

## 1. Lock the brief

Write audience, archetype, product, core offer, and action. Select one researched modernist style, one postmodernist style, and two principles.

Keep image medium consistent when possible so style and persuasion are easier to compare. Do not change everything just because a new image looks exciting.

## 2. Write two copy directions

For each principle, write headline, supporting copy, CTA, destination, and mechanism.

Example: “One version offers a useful map first; the other emphasizes neighborhood identity. Both download the same free map.”

## 3. Sketch four boxes

Label them modernist/A, postmodernist/A, modernist/B, postmodernist/B. Place headline, image, and CTA using the [anatomy diagram](01-hero-anatomy.md). Ask a teammate to identify the offer; fix unclear wording now.

## 4. Give AI a specification

Copy and complete:

```text
Create a static website hero mockup.
Audience:
Brand and archetype:
Product and core offer:
Desired action and CTA destination:
Persuasion principle and its visible mechanism:
Named design style:
Features adapted from my researched references:
Image medium, subject, crop, and gaze direction:
Exact headline:
Exact supporting copy:
Exact CTA:
Dimensions:
Keep text readable and the CTA prominent.
Do not invent endorsements, statistics, scarcity, or extra claims.
```

Change style or persuasion deliberately for subsequent versions. Save useful prompts. [Inspect the gallery prompts](../assets/tutorial/prompts.json).

## 5. Inspect before accepting

Read every word. Check hands, objects, products, and backgrounds. Does the picture explain the offer? If generated text fails, generate the visual and assemble readable copy in a design tool.

Submit static images now. Later, rebuild the layout with HTML text and working controls rather than one giant screenshot.

## 6. Get specific feedback

Show a hero briefly, hide it, then ask:

- What was offered?
- Who was it for?
- What would the button do?
- What drew your attention?

This is an informal comprehension check, not eye tracking or proof of conversion. Reopen it and use the [review checklist](../reference/git-workflow.md#review-before-merging).

Sketch a narrow-screen version too. Preserve hierarchy and a reachable CTA instead of shrinking the desktop image.

## 7. Save your reasoning

Keep one rejected draft per package. Write **“I changed ____ because feedback showed ____.”** Choose the strongest final hero and explain tradeoffs across all four. Commit images and Markdown together.

**Carry forward:** this is the process evidence already required by the assignment, not a separate exercise report.
